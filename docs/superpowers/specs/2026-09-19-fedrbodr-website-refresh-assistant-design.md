# Обновление fedrbodr.com + блок личного AI-ассистента

Дата: 2026-09-19
Linear: WOK-331
Репозитории: `fedrbodr` (сайт, статический) и `fedrbodr-studio` (AI-визард, Astro + API)

## Контекст

Сайт `fedrbodr.com` не обновлялся с 07.09 (commit `5022508`). Backlog ревизии
зафиксирован в `docs/backlog/fedrbodr-studio-site.md`; его предусловие —
готовый лендинг Studio — выполнено (`studio.fedrbodr.com` работает).

Актуальные проверяемые результаты (Linear + Control Hub, на 2026-09-19):

- KSY Deals: production-контур v0.8.4 в проде (бот, админка, сайт); пересчёт цен,
  каталог, публикации скидок и заказ собраны в один контур. Бизнес-эффект ещё
  измеряется — это граница доказательств.
- Marcel Lior: сайт сдан под ключ, в проде; идёт SEO/GEO-эксперимент.
- Клиентский пилот: завершён, принят и полностью оплачен (20 000 ₽).
- Vezdepost: в проде, 30+ платформ.
- Опыт: 20+ лет разработки, в основном fintech (Сбер, Райффайзен, Альфа,
  Crypterium), команда до 13 человек.

Владелец увидел форму диагностики на Studio и хочет переиспользовать её
на личном сайте как «консультацию личного AI-ассистента»: 3 коротких шага,
польза сразу, затем заявка на личный разбор Дмитрию.

## Утверждённые решения

1. Объём: полная ревизия контента по backlog + новый блок AI-ассистента.
2. Механика блока: живой AI-диалог через API Studio; backend Studio расширяется
   origin-allowlist'ом (CORS), AI-логика переиспользуется.
3. Появление блока: секция на странице + плавающая карточка после скролла.
4. Фокус разбора: один ручной процесс (как на Studio).
5. Trust-блок: только самозанятость + договор + чек (NDA не заявляем).
6. Заявки: в тот же операторский Telegram Studio, с пометкой источника.

## Часть 1. Studio backend (`fedrbodr-studio`)

### 1.1 Origin allowlist (TDD)

- `src/server/http.ts`: рядом с `isSameOrigin` добавить `isAllowedOrigin(request)`:
  - true, если Origin совпадает с origin сервера (как сейчас);
  - true, если Origin входит в `ALLOWED_EXTRA_ORIGINS` (env, CSV,
    например `https://fedrbodr.com,https://www.fedrbodr.com`);
  - false, если Origin отсутствует или не распознан (как сейчас).
- Middleware (`requiresSameOrigin`) и каждая защищённая переключаются с
  `isSameOrigin` на `isAllowedOrigin`.

### 1.2 CORS и preflight

- Для `/api/diagnose`, `/api/leads`, `/api/consents/diagnostic`:
  - успешные и ошибочные JSON-ответы получают `Access-Control-Allow-Origin`
    (эхо разрешённого origin) и `Vary: Origin`;
  - `OPTIONS` на этих путях отвечает 204 с `Access-Control-Allow-Methods: POST`
    и `Access-Control-Allow-Headers: content-type`.
- Остальные API-пути поведение не меняют.

### 1.3 Режим `personal`

- `diagnosticRequestSchema` + необязательное поле `mode: "studio" | "personal"`,
  по умолчанию `studio`.
- `src/features/diagnostic/prompt.ts`: два системных промпта:
  - `studio` — существующий, без изменений;
  - `personal` — «Ты — личный AI-ассистент Дмитрия Федоренко (FedrBodr), делаешь
    первичный разбор одного ручного процесса…» + правило «Отвечай на языке
    сообщения пользователя». Все ограничения существующего промпта (без цены,
    сроков, ROI, один вопрос за раз, результат после пяти ответов, high_risk
    для медицины/права/финансов) сохраняются.
- Схема результата, ограничения, рейт-лимиты, сессии — без изменений.

### 1.4 Источник лида

- `leads`-контракты: необязательное поле `source` (короткая строка, разрешённый
  набор значений: `studio`, `fedrbodr.com`).
- Значение попадает в сообщение оператору в Telegram: «источник: fedrbodr.com».
- Отсутствие поля обрабатывается как `studio` (обратная совместимость).

### 1.5 Согласие

- Блок на fedrbodr.com ссылается на существующую страницу
  `https://studio.fedrbodr.com/consent/diagnostic` (в новой вкладке).
- Голосовой ввод в v1 не переиспользуем, поэтому аудио-часть согласия на
  личном сайте не актуальна; текст страницы согласия на Studio не меняется.

### 1.6 Тесты

- Vitest-юниты: allowlist, CORS-заголовки, preflight, `mode` в контрактах и
  промптах, `source` в лидах.
- Существующие тесты не должны измениться по смыслу; интеграционные
  (playwright/vitest.integration) прогоняются как есть.

## Часть 2. Контент-ревизия `fedrbodr.com`

Страница остаётся одним статическим `index.html` (RU/EN через `data-i18n`),
без сборки и фреймворков. Новая структура секций:

1. **Hero** — новое позиционирование: «Запускаю и спасаю веб-проекты: backend,
   платежи, интеграции». MVP/SaaS — второй сценарий. «За несколько дней» —
   только про прототип/первый этап. CTA: «Обсудить задачу» → Telegram,
   «Показать, что умею» → кейсы. Чипы и подача синхронизируются.
2. **Направления (3)** — замена текущей секции `#order`:
   - доработка и спасение существующих продуктов;
   - MVP и SaaS с нуля;
   - автоматизация ручных процессов (CRM, Telegram, таблицы, AI).
   У каждой — 1–2 строки и пример результата. Сроки «от недели» оставляем
   только там, где это честно (MVP); для production-систем — «срок после
   диагностики».
3. **Кейсы (3)** — новый блок `#cases`, формат «задача → роль → решение →
   проверяемый результат»:
   - KSY Deals: ручная подготовка скидок 0,5–2 часа на цикл → контур
     пересчёта цен, каталога, публикаций и заказов → production v0.8.4 в проде;
     граница: бизнес-эффект измеряется.
   - Marcel Lior: сайт под ключ (дизайн, вёрстка, прод) → сдан; сейчас
     SEO/GEO-эксперимент.
   - Финтех-пилот (без названия клиента): диагностика и первый этап → принят
     заказчиком и оплачен.
4. **Опыт** `#experience` — факты обновляются: 20+ лет разработки (выравниваем
   с формулировкой Studio «Более 20 лет»; текущие «15+» на сайте заменяем),
   fintech, KSY в проде, пилот принят и оплачен. Убрать «следующая цель —
   первый оплаченный заказ».
5. **История** `#about` — без структурных изменений, лёгкая сверка фактов.
6. **AI-ассистент** `#assistant` — см. Часть 3.
7. **Build in public** `#build` — скрыть карточки X/vc.ru/Habr с «ссылка скоро».
8. **Контакт** `#contact` — заголовок «Нужно запустить, закончить или спасти
   веб-проект?»; пресса/выступления — одной второстепенной строкой.
9. **Trust** — компактный блок перед контакт-CTA: самозанятость, договор,
   чек. Только то, что реально предоставляется.
10. **Шоу `#show`** — секция удаляется (обещание несуществующего эпизода).
    Build-in-public остаётся единственным «журнальным» блоком.

Дополнительно:

- `robots.txt` и `sitemap.xml` (статические, с актуальными URL).
- `<title>`/meta description обновить под новое позиционирование (RU/EN).
- Панели вебмастеров и индексация — ручной шаг владельца, вне кода.

## Часть 3. Блок «личный AI-ассистент»

### 3.1 Секция `#assistant`

Между `#about` и `#build`. Подача: «Консультация моего личного AI-ассистента».
Три шага (визуально как на Studio):

1. Опишите — одну рутинную задачу своими словами.
2. Уточните — ассистент задаст несколько коротких вопросов.
3. Получите разбор — что отдать системе, что оставить человеку; затем можно
   оставить заявку Дмитрию на личный разбор.

Дисклеймер: «AI работает в заданных правилах, финальные решения принимает
человек; без расчёта цен и обещаний роста».

### 3.2 Визард (vanilla JS)

- Реализация на чистом JS в `index.html`/отдельном `assistant.js` (без React,
  без сборки), в стиле сайта (тема, `data-i18n` RU/EN).
- Шаг 1: textarea (минимум 20 символов) + чекбокс согласия со ссылкой на
  `/consent/diagnostic` Studio (новая вкладка). Отправка без согласия запрещена.
- Шаг 2: `POST https://studio.fedrbodr.com/api/diagnose` с телом
  `{ processText, answers, mode: "personal" }`; вопросы рендерятся как текст
  или радиокнопки (`single_choice`); до 5 итераций.
- Шаг 3: карточка результата — summary, «автоматизировать первым»,
  «оставить человеку», первый безопасный эксперимент; special-case для
  `not_worth_automating` и `high_risk` (мягкая формулировка, без советов).
- Заявка: форма «контакт + канал (Telegram/phone/email)» →
  `POST /api/leads` с `source: "fedrbodr.com"`; после успеха — подтверждение.
- Ошибки: недоступен AI / рейт-лимит / сеть — понятные сообщения и fallback
  «Написать в Telegram». Файлы ошибок те же коды, что отдаёт Studio.
- Голос, загрузка аудио и транскрибация в v1 не подключаются.

### 3.3 Плавающая карточка

- Компактная карточка появляется, когда посетитель проскроллил ~50% страницы
  (IntersectionObserver на якоре секции опыта).
- Кнопка ведёт к `#assistant` (плавный скролл), крестик закрывает до конца
  сессии (`sessionStorage`).
- Не перекрывает контент на мобильных (отступы, maxWidth), уважает тему.

### 3.4 Тесты (TDD)

- Расширить существующие `.mjs` content-тесты:
  - hero/направления/кейсы/CTA/trust — наличие и отсутствие запрещённых
    формулировок («следующая цель — первый оплаченный заказ», «ссылка скоро»,
    «Смотреть шоу»);
  - RU/EN парность `data-ru`/`data-en` для всех новых узлов;
  - блок ассистента: секция, 3 шага, чекбокс согласия, ссылка на Studio,
    `mode: "personal"`, `source: "fedrbodr.com"` в отправке, обработка ошибок;
  - плавающая карточка: поведение показа/скрытия, sessionStorage;
  - `robots.txt`/`sitemap.xml` существуют и содержат канонический URL.

## Порядок реализации

1. Studio: TDD-волны 1.1 → 1.2 → 1.3 → 1.4; полный прогон тестов; деплой
   Studio; проверка живого API с origin fedrbodr.com (curl с `Origin`).
2. fedrbodr: TDD-волны контента (Часть 2), затем визард (Часть 3); прогон
   тестов; локальная проверка страницы.
3. Деплой fedrbodr.com (`deploy.sh`), smoke-проверка на проде: визард до
   результата, заявка с `source: fedrbodr.com` приходит в Telegram.
4. Linear WOK-331 → Done, checkpoint в Control Hub.

## Риски и границы

- Studio-проект формально на паузе; изменение только техническое (allowlist,
  режим, источник), продуктовых обещаний не добавляет.
- CORS открывается точечно на три маршрута и один origin; rest API остаётся
  закрытым. Отсутствие Origin по-прежнему отклоняется.
- Данные из формы идут по существующему согласию Studio; аудио не собираем.
- Хостинг fedrbodr.com — FTP-деплой статики; серверной логики на этом домене
  не появится.

## Вне объёма (не делаем)

- Голосовой ввод на личном сайте.
- Личный бэкенд/БД на fedrbodr.com.
- Панели вебмастеров, рекламные счётчики.
- Изменения продуктовых обещаний Studio.
