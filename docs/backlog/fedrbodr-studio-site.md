# FedrBodr Studio: отложенный backlog личного сайта

## Статус

**Отложено.** До отдельного решения о старте проекта FedrBodr Studio сайт
`fedrbodr.com` не переделываем.

Предварительное условие старта: закончить и принять продающий лендинг студии,
чтобы личный сайт мог вести клиента в готовую точку продажи. После этого пункты
из этого документа нужно перенести в backlog отдельного проекта и уточнить по
актуальному состоянию бизнеса.

Рабочее направление для названия — **FedrBodr Studio**. Это пока не финальное
решение о бренде или юридическом оформлении.

## Роль сайтов

- Сайт студии продаёт разработку и автоматизацию бизнеса.
- `fedrbodr.com` показывает опыт основателя, реальные проекты и кейсы, создаёт
  доверие и ведёт подходящего клиента в студию.
- Личный сайт не должен дублировать весь продающий лендинг студии.

## Проекты и кейсы для будущей сверки

- **KSY Deals / KSY Store** — активный кейс автоматизации; публичное описание
  обновить после готовности кейса и использовать уже достигнутый результат.
- **Marcel Lior** — завершённый оплаченный кейс разработки сайта.
- **IMVU-направление** и **Vezdepost** — активные собственные продукты; перед
  публикацией сверить их текущие статусы.
- **GoProWever** — на паузе до оформления международного юридического лица
  студии; не показывать как проект «в работе».
- Внутренние Idea Hunter, Personal OS и эксперимент с Claude не использовать
  как клиентские доказательства.

## Backlog будущей переработки

1. На первом экране заменить узкое обещание «MVP за несколько дней» на основное
   позиционирование про запуск и спасение веб-проектов, backend и платежи. MVP и
   SaaS оставить вторым сценарием.
2. Развести три направления:
   - доработка существующих продуктов;
   - создание MVP и SaaS с нуля;
   - автоматизация ручных процессов через CRM, Telegram, email, таблицы и AI.
3. Формулировку «за несколько дней» оставить только для прототипа или
   ограниченного первого этапа. Для production-систем называть срок после
   диагностики или discovery.
4. Заменить заголовок «Партнёрство, пресса или спикерство?» на клиентский CTA:
   «Нужно запустить, закончить или спасти веб-проект?». Прессу и выступления
   вынести во вторичный блок.
5. Добавить минимум три доказательных кейса:
   - fintech и платежи;
   - спасение или завершение существующего продукта;
   - автоматизация ручного процесса.

   Для каждого показать задачу, роль, решение и проверяемый результат. Закрытые
   проекты можно описывать без названия клиента.
6. Не использовать карточку с формулировкой «следующая цель — первый оплаченный
   заказ» как главное доказательство коммерческого опыта. Показывать уже
   полученный результат пилота либо переносить карточку в build-in-public.
7. Пересмотреть роль `zero-to-prod`: рекомендуемый вариант — удалить обещание
   несуществующего шоу. Если формат будет сохранён, переместить его вместе с
   build-in-public ниже услуг, опыта и кейсов, чтобы он не перехватывал основной
   клиентский сценарий.
8. Скрыть неготовые ссылки X, vc.ru и Habr до появления реальных страниц.
9. Добавить доверительный блок: самозанятость, договор, чек и NDA. Указывать
   только то, что студия действительно готова предоставлять.
10. Проверить индексацию домена, `robots.txt`, `sitemap.xml` и подключение
    панелей вебмастеров: сайт открывается напрямую, но пока не находится поиском
    по домену.

## До выполнения предварительного условия

- не менять `index.html` по этим пунктам;
- не создавать подпроект и Linear backlog только ради хранения заметок;
- не менять публичное позиционирование и не запускать новый деплой;
- после готовности лендинга Studio повторно сверить факты, кейсы, CTA и
  юридические формулировки.
